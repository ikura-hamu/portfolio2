## セッション

聴いたセッションの中から印象に残ったものを書きます。Vue Fes ですが全体として Vue の話は少なくてツールチェーンに焦点を当てた話が多かった気がします。個人的にはそっちの方が興味あるので嬉しかったです。

### キーノート

Evan You さんのキーノートでは、Cloudflare (VoidZero) が取り組んでいるツールチェーン周りを知ることができました。最近出たフルスタックフレームワークの Void がいいなと思いました。Cloudflare アカウントがいらないみたいなことを言ってた気がするんだけどどういうことだろう。

Tool design has a second audience (人間だけじゃなくてエージェント向けのツール設計が必要). という主張がありました。これはフロントエンドや JavaScript に関わるもので、これができる言語やエコシステムが今後生き残るんだろうなと思いました。

これだけフロントエンド周りに貢献している VoidZero が Cloudflare に入ったことでお金を気にしなくて良くなったのはすごいいいなと思いました。

### AstroとRustで考えるフロントエンドツールチェーンの今

このブログサイトは Astro でできているので聴きに行きました。Gopher としては Astro が Go をやめてしまったのは少し残念だったので、その理由も気になっていました。

以前の Astro コンパイラが Lint や Format といった処理を行うために色んな変換やエッジケースの対応をたくさんする必要があり大変だったが、Oxc parser の実装を活用することでその課題を解決できたということだったと思います。いろんなツールチェーンが Rust になったのを活かして、それらを取り込んでいくのはとても合理的だと思いました。

また、コンパイルするだけじゃなくて Linter とか Formatter も実装する必要があるのは大変だなと感じました。おそらくほんとにコンパイルするだけなら考えることは少なくて、Lint にも Format にも型チェックにも Language Server にも使える表現を扱うのが難しいと思いました。

### Vite Task’s Cache Magic

Vite+ のタスクランナーのキャッシュがすごいという話です。リリースされたときにその話は少し聞いていましたが、改めてトークを聴いて良い解決だなと思いました。この仕組みすごいいいと思うので他のタスクランナーでも取り入れてほしいんですけど、あまり実装されたという話を聞かない気がするのはなんでなんでしょうか。

ここでもエージェントの話が出てきており、たくさんコマンドが実行されるからキャッシュで高速化するの大事ということでした。

開発中の CI で使える Remote cache の話もありました。エージェントの影響で PR の数がめっちゃ増えて CI に時間がかかってしょうがないという話はよく聞くので、ぜひ実現してほしいと思います。バックエンドに Cloudflare Workers を使うらしく、難しそうなキャッシュ管理を移譲できるの助かると思いました。
Go にも似た仕組みとして、ビルドキャッシュを取得するプログラムを指定できる`GOCACHEPROG`がありますが、これは結局ネットワークがボトルネックになって、大幅な速度改善が難しいと聞いたことがあります。Vite+ も Remote Cache 同じ問題に直面しそうですがどうなんでしょうかね。Cloudflare のエッジコンピューティングパワーでどうにかなるんでしょうか。
