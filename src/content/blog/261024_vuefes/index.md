2026 年 10/24 (今日)開催された Vue Fes Japan 2026 に参加しました。

自分は普段はもっぱら Go でサーバーを書いてるのですが、フロントエンドを書く技術を選んでいいと言われたら Vue を選ぶという感じです。大きいプロジェクトで Vue を使ったことはありません。

この記事は急いで書いたので、不正確な記述を含む可能性があります。

## セッション

聴いたセッションの中から印象に残ったものを書きます。Vue Fes ですが全体として Vue の話は少なくてツールチェーンに焦点を当てた話が多かった気がします。個人的にはそっちの方が興味あるので嬉しかったです。

### キーノート

Evan You さんのキーノートでは、Cloudflare (VoidZero) が取り組んでいるツールチェーン周りを知ることができました。最近出たフルスタックフレームワークの [Void](https://void.cloud/) がいいなと思いました。Cloudflare アカウントがいらないみたいなことを言ってた気がするんだけどどういうことだろう。

Tool design has a second audience (人間だけじゃなくてエージェント向けのツール設計が必要). という主張がありました。これはフロントエンドや JavaScript に関わらず、いろんな分野でこれができる言語やエコシステムが今後生き残るんだろうなと思いました。

最近は TypeScript (tsgo) をいろんな言語に移植して速くなったと主張するのが流行っています。自分はこのあと TypeScirpt どうなるんだと混乱していましたが、影響力のある VoidZero が Rust 実装の tsrs を TypeScript チームと協力のもと公開してくれたので安心しました。実装が乱立すると差分とかで大変になると思うので、うまくコントロールしてやってほしいなと思います。

これだけフロントエンド周りに貢献している VoidZero が Cloudflare に入ったことで、お金を気にしなくて良くなったのはすごくいいなと思いました。

### AstroとRustで考えるフロントエンドツールチェーンの今

https://vuefes.jp/2026/speaker/jp-knj

このブログサイトは Astro でできているので聴きに行きました。Gopher としては Astro が Go をやめてしまったのは少し残念だったので、その理由も気になっていました。

以前の Astro コンパイラが Lint や Format といった処理を行うために色んな変換やエッジケースの対応をたくさんする必要があり大変だったが、Oxc parser の実装を活用することでその課題を解決できたという話だったと思います。いろんなツールチェーンが Rust になったのを活かして、それらを取り込んでいくのはとても合理的だと思いました。

また、コンパイルするだけじゃなくて Linter とか Formatter も実装する必要があるのは大変だなと感じました。おそらくほんとにコンパイルするだけなら考えることは少なくて、Lint にも Format にも型チェックにも Language Server にも使える表現を扱うのが難しいんだろうなと思いました。

### Vite Task’s Cache Magic

https://vuefes.jp/2026/speaker/wan9chi

Vite+ のタスクランナー（`vp run`）のキャッシュがすごいという話です。リリースされたときにその話は少し聞いていましたが、改めてトークを聴いて良い解決方法だなと思いました。この仕組みはすごい良いと思うので他のタスクランナーでも取り入れてほしいのですが、あまり実装されたという話を聞かない気がするのはなんでなんでしょうか。

ここでもエージェントの話が出てきており、たくさんコマンドが実行されるからキャッシュで高速化するの大事ということでした。

開発段階である、CI で使える Remote cache の話もありました。エージェントの影響で PR の数がめっちゃ増えて CI に時間がかかってしょうがないという話はよく聞くので、ぜひ実現してほしいと思います。バックエンドに Cloudflare Workers を使うらしく、難しそうなキャッシュ管理を移譲できるのは助かると思いました。
Go にも似た仕組みとして、ビルドキャッシュを取得するプログラムを指定できる`GOCACHEPROG`がありますが、これは結局ネットワークがボトルネックになって、大幅な速度改善が難しいと聞いたことがあります。Vite+ も Remote Cache 同じ問題に直面しそうですがどうなんでしょうかね。Cloudflare のエッジコンピューティングパワーでどうにかなるんでしょうか。

### The Vue Toolchain, Reimagined

https://vuefes.jp/2026/speaker/ubugeeei

主に Vue の Rust 製ツールチェーンの [Vize](https://github.com/ubugeeei-prod/vize) の開発についての話でした。ここでもエージェントがツールたくさん呼ぶから速い方がいいという話でした (Human + Tooling in the Loop)。

ここも Astro のトークと同様に、 Oxc を使ってパースして独自の事後処理を実装しているらしいです。Oxc はあまり知らなかったんですが、そんなにたくさん活用されているんですね。

Vize の機能としていいなと思ったのは、ファイルをまたいだ template の複雑度のチェックです。状態が増えて複雑になると人間も AI も把握が難しくなると思うので、あるととても便利だと思いました。

また、Vize の開発では既存の Vue 製 OSS を使ってテストをしているという話がありました。Vue の出力と Vize の出力を比較してテストしているそうです。OSS パワー！という感じがしてとても好きでした。

最後に Shared semantics の話がありました。Vue とか JSX を共通の中間表現 (Shared semantics) にまとめてコンパイルとか Lint に使おう、将来的には他の記法にも対応しよう、ということでした。ネイティブ言語における LLVM っぽいなと思いました。そう考えると今までなかったのは不思議ですね。

---

一貫して「エージェントがツールをたくさん実行するからその速度がボトルネック」ということを話していたスピーカーの方が多かったと思います。他の言語でも同じだと思うので、いろいろ考えていきたいです。
